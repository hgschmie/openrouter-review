# Support and reporting

OpenRouter Review generates AI suggestions that can be incorrect, incomplete, or inappropriate. Reporting a problem helps the maintainer reproduce it and decide whether a code, prompt, or documentation change is needed. Support is provided on a best-effort basis; no response-time guarantee is offered.

## Report to the maintainer

Use the [AI review feedback form](https://github.com/hgschmie/openrouter-review/issues/new?template=ai-review.yml) for false positives, missed issues, unsafe suggestions, prompt injection, or inappropriate output. [File a GitHub issue](https://github.com/hgschmie/openrouter-review/issues/new/choose) for other bugs and questions.

Public reports should include the action tag or commit, model ID, relevant settings with credentials removed, expected behavior, and a small synthetic reproduction. Include a sanitized excerpt of the output only if it is safe to publish. A screenshot can still expose private code or identities. Do not attach full workflow logs, real secrets, private repository contents, personal information, or offensive material when a description is sufficient.

For security or privacy concerns, [file a GitHub issue](https://github.com/hgschmie/openrouter-review/issues/new/choose) with only a brief description that is safe to share publicly. Issues are public, and private GitHub vulnerability reporting is not currently enabled for this repository. Do not include sensitive vulnerability details, credentials, private code, or personal data.

If a review exposes a credential, notify the repository owner and revoke or rotate the credential promptly. Remove the exposed review where authorized and contact the relevant provider about retained copies. Deleting a GitHub comment alone does not revoke a key or erase data already sent elsewhere.

## Report to GitHub

For content that violates GitHub's policies, use **Report content** on the comment where available, **Report repository**, or the Marketplace listing's **Report abuse** link after it is published. GitHub documents these routes in [Reporting abuse or spam](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam). You can also contact [GitHub Support](https://support.github.com/contact) for platform problems.

Reporting to GitHub and reporting to this project's maintainer are separate actions; an issue here is not automatically forwarded to GitHub. A review's disclosure links to both reporting routes. For billing, account restrictions, or retention questions at the model service, contact that service using its support channel; do not send API keys to this project's maintainer.

See the [privacy notice](PRIVACY.md) for what is sent to each service and how to request removal of records.
